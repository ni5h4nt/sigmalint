# v0.1.4 Implementation Plan — ATK + RED + STY Contrived Shape Coverage

> **For Claude:** REQUIRED: Use the `casef` skill to execute this plan.

**Goal:** Extend the contrived rule-shape test methodology established in v0.1.2 (TAX) and v0.1.3 (FP + META) to the ATT&CK, redundancy, and style dimensions (9 rules total: ATK001-004, RED001-002, STY001-003), fixing any defect surfaced by the shape distribution.

**Architecture:** Same as prior rollouts — each rule gets a `tests/contrived/<RULE_ID>/` directory with a `manifest.yml` + per-case `pos_*`/`neg_*`/`edge_*` fixtures, registered in `_RULE_MAP` in `tests/contrived/test_contrived.py`. Two of the three dimensions (ATK, RED) read from a context-provider the contrived harness does not yet supply, so each needs a small `_ctx()` extension analogous to the v0.1.3 `filters:` field. Any defect surfaced by the new fixtures gets fixed in-PR via the source change that makes the contrived suite pass.

**Tech Stack:** Python 3.10–3.13, hatchling, pytest, ruff, mypy. No new dependencies.

**Release boundary:** Single v0.1.4 release after all PRs merge. Serial PR execution — each builds on the previous one's merged state. PR ordering is by ascending harness cost: **STY (no provider) → ATK (attack provider) → RED (fake corpus) → release-cut.**

## PR #C — RED dimension (fake-corpus harness extension)

## Phase 11: PR-C.1 RED harness extension — inject a fake corpus [depends: 10] [est: ~120 lines]

**Files:**
- Modify: `tests/contrived/test_contrived.py` — add a `corpus:` manifest field + `_build_corpus()` helper, wire into `_ctx()`

**Why a fake (not the real `RuleCorpus`).** `RuleCorpus(data_dir)` builds its index from cloned SigmaHQ rules on disk (`data/corpus.py:_build_index`); reproducing that in a contrived fixture is heavy and non-deterministic across corpus refreshes. RED only touches three members of the corpus object:

- `corpus.available` (bool)
- `corpus.near_duplicates(fp, threshold) -> list[match]` where each match has `.path`, `.title`
- `corpus.entries() -> list[CorpusEntry]` where each entry has `.id`, `.title`, `.path`

A small in-process fake satisfying exactly that surface lets the manifest declare the corpus contents per-case (mirrors the v0.1.3 `filters:` extension exactly).

**Concrete API** (verified from `src/sigmalint/data/corpus.py`):

```python
@dataclass(frozen=True)
class CorpusEntry:   # confirm field names/order against corpus.py:25
    id: str
    title: str
    path: str
    # ... fingerprint/tokens field used by near_duplicates
```

**Harness sketch:**

```python
class _FakeCorpus:
    def __init__(self, entries, near):
        self._entries = entries          # list[CorpusEntry]
        self._near = near                # list of (path, title) to return from near_duplicates
        self.available = True

    def entries(self):
        return self._entries

    def near_duplicates(self, fp, threshold):
        # Contrived: ignore fp/threshold, return manifest-declared matches.
        # (Real Jaccard math is unit-tested separately; here we test the
        #  rule's *handling* of matches, not the similarity metric.)
        return self._near
```

Manifest schema gains an optional per-case `corpus:` block:

```yaml
positives:
  - file: pos_near_duplicate.yml
    expect: 1
    corpus:
      near_duplicates:
        - {path: "rules/windows/foo.yml", title: "Existing Rule"}
```

**Decision point — fidelity of `near_duplicates`.** Two options, pick in-phase:

| Option | Trade-off |
|---|---|
| **(preferred)** Fake returns manifest-declared matches verbatim (above). Tests the rule's match-handling: the `m.path == parsed.path` self-skip, the `[:3]` cap, the per-match emission. | Decouples RED001 shape coverage from the Jaccard metric (which has its own unit tests) |
| (alternative) Fake computes real Jaccard over manifest-supplied corpus fingerprints | Higher fidelity but re-tests metric logic already covered elsewhere; brittler fixtures |

- [ ] **Step 1: Confirm `CorpusEntry` field names + the match object shape returned by the real `near_duplicates`** (so the fake's duck-type matches)
- [ ] **Step 2: Implement `_FakeCorpus` + `_build_corpus()` + `_ctx()` wiring (default: no corpus → `available` absent/False, preserving current early-return behaviour for non-RED dimensions)**
- [ ] **Step 3: No-regression smoke check on an existing dimension**
- [ ] **Step 4: Commit the harness extension alone**

```bash
git add tests/contrived/test_contrived.py
git commit -m "test(contrived): inject fake corpus for RED coverage

  RED001/002 return early without ctx.corpus. Add a duck-typed
  _FakeCorpus driven by a manifest `corpus:` block so near-duplicate
  and id/title-collision shapes can be exercised deterministically,
  without cloning SigmaHQ."
```

## Plan-level score-impact protocol

Same protocol as v0.1.2/v0.1.3 for any phase that fixes source code (vs. fixture-only changes):

1. After the fix, run `sigmalint lint /tmp/sigmahq-corpus/rules --format json` with both the pre-fix (v0.1.3 from PyPI) and post-fix (local editable install) binaries.
